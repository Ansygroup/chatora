Chatora API and MCP

A free REST API and a remote MCP server for your own workspace. You can read contacts, flows and conversations, and create contacts. Nothing here sends a message to anyone.

1. Create a key

Sign in, open Settings, Developers and API, pick the scopes and create a key. The key looks like chk_live_ plus 40 hex characters. It is shown once. Chatora stores only a hash of it, so a lost key cannot be recovered: delete it and make a new one. Up to 5 keys per workspace.

ScopeAllows
contacts:readList contacts
contacts:writeCreate a contact (free plan limit: 100 contacts). Does not start a conversation.
flows:readList flows (name, channel, status, step count)
conversations:readList conversations and read their messages
events:writePush contact events (tag, enroll, unenroll) that start flows
hooks:writeManage outbound webhook subscriptions and read delivery samples
messages:writeSend a Telegram message to a contact the workspace already has

2. REST API

Base URL https://chatora.us.ci/api/v1. Send the key as a Bearer token. A key without the needed scope gets 401. Limit: 120 requests per 10 minutes per key (429 after that). The OpenAPI 3 spec is at /api/v1/openapi.json.

curl https://chatora.us.ci/api/v1/contacts?limit=20 \
  -H "Authorization: Bearer chk_live_YOUR_KEY"

curl -X POST https://chatora.us.ci/api/v1/contacts \
  -H "Authorization: Bearer chk_live_YOUR_KEY" -H "Content-Type: application/json" \
  -d '{"name":"Sara","handle":"@sara","channel":"instagram","tags":["lead"],"fields":{"city":"Cairo"}}'

2a. Events (inbound)

Push an event for a contact. Chatora finds or creates the contact by handle, applies the side effect and starts every live flow whose trigger matches. This is how Zapier, Make, n8n or Google Apps Script start automations in Chatora. Limit: 60 events per 10 minutes per key.

curl -X POST https://chatora.us.ci/api/v1/events \
  -H "Authorization: Bearer chk_live_YOUR_KEY" -H "Content-Type: application/json" \
  -d '{"event":"tag-applied","handle":"sara@example.com","name":"Sara","key":"vip"}'
eventkey carriesSide effect
tag-appliedtag textAdds the tag; starts flows triggered by event:tag-applied <tag>
tag-removedtag textRemoves the tag; starts flows triggered by event:tag-removed <tag>
field-changedfield nameStarts flows triggered by event:field-changed <field>
enrollflow id (see GET /flows)Starts that flow for the contact
unenrollflow idStops the contact's running or pending runs of that flow

Handles that look like tg:123456789 or web:abcdef12 get the matching channel automatically, so flow messages reach Telegram or the web inbox.

2b. Webhooks (outbound, Zapier/Make/n8n)

Subscribe a URL and Chatora POSTs JSON each time the event happens, with an x-chatora-event header. Events: contact.created, message.received, event.received, flow.finished. Up to 10 subscriptions per workspace. You can also manage subscriptions in Settings, no code needed.

# Subscribe (Zapier REST Hooks call this automatically)
curl -X POST https://chatora.us.ci/api/v1/hooks \
  -H "Authorization: Bearer chk_live_YOUR_KEY" -H "Content-Type: application/json" \
  -d '{"event":"message.received","target_url":"https://hooks.zapier.com/hooks/catch/..."}'

# Sample data / polling fallback: bare array, newest first
curl "https://chatora.us.ci/api/v1/hooks/samples?event=message.received" \
  -H "Authorization: Bearer chk_live_YOUR_KEY"

# Unsubscribe
curl -X DELETE https://chatora.us.ci/api/v1/hooks/SUBSCRIPTION_ID \
  -H "Authorization: Bearer chk_live_YOUR_KEY"

Delivery body: {"id": 123, "event": "message.received", "created_at": "...", ...event fields}. The step-by-step Zapier, Make and n8n recipes are in the integrations guide.

2c. Send a Telegram message

curl -X POST https://chatora.us.ci/api/v1/messages/send \
  -H "Authorization: Bearer chk_live_YOUR_KEY" -H "Content-Type: application/json" \
  -d '{"handle":"tg:123456789","text":"Your order is on its way."}'

Only works for contacts the workspace already has, through the connected Telegram bot. Limit: 30 per 10 minutes per key. WhatsApp and Instagram sending are not available yet (Meta approval pending).

3. MCP (remote)

Endpoint https://chatora.us.ci/mcp (Streamable HTTP, stateless, JSON responses, POST only). Authenticate with the same Bearer key. Tools: list_contacts, create_contact, list_flows, list_conversations, get_conversation_messages. Each tool needs the matching scope.

{
  "mcpServers": {
    "chatora": {
      "url": "https://chatora.us.ci/mcp",
      "headers": { "Authorization": "Bearer chk_live_YOUR_KEY" }
    }
  }
}

Privacy

A key can only reach the workspace that created it. Conversation messages contain your customers' text, so give conversations:read only to tools you trust. Delete a key in Settings to stop it at once.
