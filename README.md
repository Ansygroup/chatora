# Chatora — معاينة منتج لمنافس ManyChat (دارك نيون + موشن + ست لغات)

موقع تسويقي من 28 صفحة مبني بـ HTML/CSS/JS خالص، مع صفحة دخول وداشبورد. اكتملت قواميس اللغات الست محليًا: الإنجليزية والعربية والإسبانية والفرنسية والألمانية والبرتغالية، ولكل منها مسارات HTML ثابتة خاصة. هذا البناء المحلي لم يُنشر إلى الإنتاج، والمعاينة لا تفعّل الإرسال عبر القنوات أو ردود الذكاء الاصطناعي أو الفوترة.

---

## 1) افتح الموقع

- **المعاينة السريعة:** افتح `index.html` مباشرة في المتصفح.
- **التشغيل المحلي بسيرفر (أفضل للتجربة الكاملة):**
  ```bash
  cd chatora
  python3 -m http.server 8000
  # ثم افتح http://localhost:8000
  ```

## 2.5) تسجيل الدخول والداشبورد (حقيقي، مش ديمو)

| الصفحة | إيه اللي فيها |
|---|---|
| `login.html` | 3 تابات: `signin` / `signup` / `magic` (لينك على الإيميل) + زر جوجل. صفحة مستقلة بدون هيدر الموقع، `noindex` وممنوعة في `robots.txt`. |
| `app.html` | داشبورد بمساحة عمل: **نظرة عامة** تعرض بيانات مساحة العمل الفعلية، أو حالة فارغة بلا سجلات تجريبية · **الإنبوكس** يعرض المحادثات الواردة؛ الإرسال وبدء محادثة متوقفان إلى أن تُربط قناة رسمية · **السيناريوهات** (45 قالبًا قابلة للتحرير كمسودات؛ تشغيل تجريبي داخل المتصفح فقط؛ تفعيل الأتمتة متوقف لحين الربط) · **جهات الاتصال** (إضافة/تعديل/حذف + بحث + وسوم + استيراد/تصدير CSV؛ ملف القالب فارغ بلا أسماء وهمية) · **البثّ الجماعي** معاينة جمهور فقط، والإرسال معطّل ولا ينشئ سجلات رسائل وهمية · **الإعدادات** (اسم مساحة العمل، تغيير كلمة المرور، تنزيل نسخة JSON، تسجيل خروج، وبطاقات ربط Meta المقفولة حتى تجهيز التطبيق والقاعدة) · مبدّل لغة داخل الداشبورد للغات الست، مع تحويل RTL للعربية. |

**تدفق الحسابات موصول برمجيًا** بـSupabase Auth (كلمة سر، لينك إيميل، Google)، والداشبورد مصمم لمساحة عمل حقيقية لا لبيانات ديمو. لم نتحقق من إعدادات المزودين أو اتصال المشروع الحي في هذا التدقيق المحلي؛ قد تتطلب روابط البريد وGoogle إعدادات إضافية.
كل مستخدم يفترض أن يرى بياناته فقط — الحماية بقواعد **RLS** على 6 جداول
(`workspaces`, `flows`, `contacts`, `conversations`, `messages`, `broadcasts`)، والقاعدة:
`workspace_id in (select id from workspaces where owner = auth.uid())`.

**أول دخول:** مفيش trigger على السيرفر؛ `assets/js/app.js` ينشئ مساحة عمل فارغة فقط. لا يضيف جهات اتصال أو سيناريوهات أو محادثات تجريبية. القالب لا يُحفظ إلا بعد أن يختاره المستخدم، ويُضاف كمسودة. حذف الحساب من `auth.users` يمسح بيانات مساحة العمل المرتبطة به (`on delete cascade`).

| الملف | وظيفته |
|---|---|
| `assets/js/config.js` | `SUPABASE_URL` + `SUPABASE_ANON_KEY` + إعدادات Meta العامة؛ App ID وConfig IDs فاضيين حاليًا، ومسار WhatsApp محدد `tech_provider` بناءً على اختيار المستخدم. ممنوع وضع أي App Secret أو System Token أو مفتاح تشفير هنا. |
| `assets/js/auth.js` | عميل GoTrue/PostgREST بدون SDK: تسجيل، دخول، لينك، خروج، تجديد توكن، `rest()` |
| `assets/js/login.js` | تحكم صفحة الدخول (تابات + رسائل خطأ بالعربي والإنجليزي + **نسيت الباسورد** + شاشة «باسورد جديد» اللي بتفتح من لينك الاسترجاع) |
| `assets/js/app.js` | تحكم الداشبورد (إنشاء مساحة فارغة + الشاشات + حفظ البيانات الفعلية + **polling كل 15 ثانية** للمحادثات + استيراد/تصدير CSV؛ لا يرسل رسائل قبل تفعيل قناة فعلية)؛ يقرأ اللغة من مسار ثابت `/(ar|es|fr|de|pt)/`، ويعيد التحميل عند التبديل بين أي لغتين. |
| `assets/js/templates-data.js` | بيانات القوالب الـ45 بالإنجليزية والعربية التي يقرأها معرض الداشبورد؛ تُزامَن يدويًا مع `_pages/templates.html` وقاموس `i18n-pages.js` |

**تحقق قبل اختبار طرق الدخول الحية:**
1. **Google**: يحتاج OAuth client وcallback في Supabase Authentication؛ إعداد المزود لم يُتحقق منه خلال هذا التدقيق المحلي.
2. **روابط الإيميل**: تعتمد على إعداد مزود البريد/SMTP وحدود الإرسال في المشروع. تعذّر اختبار تسليم البريد من دون اتصال حي. تسجيل كلمة السر يظل متوقفًا على إتاحة Supabase Auth.

## 3) الميزات التقنية

- **موشن حقيقي بدون مكتبات:** Aurora متحرك، Spot-light يتبع الماوس، Reveal عند التمرير، عدّادات أرقام، شات متحرك داخل موك-أب موبايل، Marquee لوجوهات، Scroll-progress، بارالاكس خفيف.
- **ديمو تفاعلي:** زر «Watch demo» يفتح مودال محادثة تُكتب لحظيًا (مع زر Replay).
- **أسعار ديناميكية:** تبديل شهري/سنوي مع أنيميشن الأرقام.
- **حاسبة ROI** تحسب فرق التكلفة شهريًا وسنويًا.
- **محرر سيناريوهات تفاعلي** (`playground.html`): ٨ أنواع عُقد، سحب وإفلات بالماوس واللمس، روابط تُرسم تلقائيًا، ٤ نماذج جاهزة، تشغيل محاكاة بسجل خطوات، وحذف بلوحة المفاتيح.
- **معرض ٤٥ قالب** بفلترة فورية وبحث + حالة "لا نتائج".
- **معرض القوالب جوّه الداشبورد**: 45 قالبًا من `templates-data.js` بفلترة وبحث؛ «استخدم القالب» ينشئ مسودة قابلة للتحرير في حالة `draft` مع خطوات عامة نائبة، لا خطوات مضبوطة حسب وصف القالب. يلزم ربط قناة ومحرك تشغيل قبل أي تفعيل؛ لا يوجد API جديد.
- **CSV portability لجهات الاتصال**: استيراد بحد 2 ميجابايت/2,000 صف، معاينة للجديد والمكرر والمتخطى، كشف تكرار بالقناة + المعرّف، أعمدة EN/AR، فواصل `,` و`;` ووسوم مقتبسة؛ أو تنزيل نموذج. التصدير ينزّل كل النتائج أو نتيجة البحث الحالية، مع UTF-8 BOM وحماية من صيغ spreadsheet؛ الاستيراد يزيل بادئة الحماية عشان الـround-trip ما يغيّرش المعرّفات.
- **القوالب العامة بتفتح القالب المقابل جوّه التطبيق**: كل CTA يحمل `app.html?view=templates&tpl=<slug>`، ولو الزائر مش مسجّل بيرجع لنفس القالب بعد التسجيل/الدخول. رابط `Product` في الناف يودّي لقسم `#product` في الرئيسية، EN وAR وباقي ترجمات الموقع.
- **تغطية اللغات في البناء المحلي: EN + AR + ES + FR + DE + PT بنسبة 100.0% لكل لغة.** اكتملت ترجمة مقالات بدائل ManyChat (`a1`)، ومبيعات رسائل Instagram (`a2`)، وتجارة WhatsApp في منطقة MENA (`a3`)، وأسعار ManyChat (`a4`)، وأدوات أتمتة Instagram (`a5`)، وتسعير WhatsApp API في مصر (`a6`)، ورسائل استعادة السلال عبر WhatsApp (`a7`)، ومقارنة ManyChat وChatfuel (`a8`)، وتسعير Chatfuel (`a9`). اكتمل أيضًا تعريب واجهة الداشبورد الديناميكية والمقارنة والتذييل والنص البديل للصور؛ لا مفاتيح ناقصة ولا fallbacks وفق فحص البناء. لكل لغة الآن 28 صفحة HTML ثابتة: EN في الجذر، وAR تحت `/ar/`، وES/FR/DE/PT تحت مساراتها. محدد اللغة ينتقل بين الصفحات الثابتة بدل الاكتفاء بـ`?lang=`. هذه مخرجات محلية فقط؛ لم يحدث نشر إلى الإنتاج.
- **Accessibility:** skip-link، ARIA على الأكورديون/المودال/القائمة، `prefers-reduced-motion`، تباين ألوان مدروس.
- **خطوط محلية (self-hosted)** — لا يعتمد على CDN، يعمل أوفلاين.

## 4) السيو (SEO)

- `<title>` و`meta description` و`canonical` لكل صفحة.
- **hreflang متبادل للغات الست** (`en`, `ar`, `es`, `fr`, `de`, `pt`) مع `x-default` إلى الإنجليزية، و`canonical` مستقل لكل صفحة/لغة. الصفحات التي تحمل `noindex` و404 لا تدخل sitemap ولا تعلن hreflang.
- **Schema.org JSON-LD:** Organization، WebSite، SoftwareApplication، FAQPage، Product، BreadcrumbList، Article. لا يوجد `Review` أو `AggregateRating`.
- `sitemap.xml` + `rss.xml` + `robots.txt` + `llms.txt` (ملخّص للبوتات الذكية) + `og.jpg` (1200×630) للشير.
- بنية عنوانين (H1→H2→H3) صحيحة، وروابط داخلية بين المقارنة/الأسعار/المقالات (محور بناء سلطة للكلمة `ManyChat alternative`).
- نصوص طويلة حقيقية قابلة للفهرسة — مش مجرد لاندنج فاضي.

> الدومين العام المقصود هو `https://chatora.ansygroup.com`، وهو مضبوط في أدوات بناء EN وAR وبقية اللغات. إعداد DNS/CNAME يظل خطوة مالك الدومين؛ لم نتحقق من DNS أو حالة النشر في هذا التدقيق.

## 5) البناء والتعديل

> آخر خطوة في البناء هي `_tools/stamp.py`: بيلزق `?v=<hash>` على كل ملف CSS/JS في HTML لكل اللغات، حتى يظهر تعديلك رغم تخزين المتصفح أو الـCDN. يشغّله `build.py` تلقائيًا بعد بناء العربية ومرايا ES/FR/DE/PT.

الموقع مقسّم لـ **قوالب** عشان تعدّل الهيدر/الفوتر مرة واحدة:

```
_partials/     ← head.html, header.html, footer.html, cta.html
_pages/        ← جسم كل صفحة (بدون head/header/footer)
_tools/build.py ← يدمج القوالب؛ يشغّل build_ar.py ثم build_locales.py ويحدث sitemap + stamps
_tools/build_locales.py ← يبني ES/FR/DE/PT، metadata وJSON-LD وروابط hreflang المتبادلة
```

بعد أي تعديل:
```bash
python3 _tools/build.py
python3 _tools/linkcheck.py  # تحقق محلي بلا شبكة من روابط الملفات والمراسي في EN/AR/ES/FR/DE/PT
```

ملفات EN النهائية في الجذر، ونسخ اللغات في مجلدات `/ar/`, `/es/`, `/fr/`, `/de/`, `/pt/` هي نواتج البناء. لا ترفعها للإنتاج قبل موافقة نشر صريحة.

## 6) النشر

حالة Vercel وSupabase وDNS **غير متحققة في هذا التدقيق المحلي**؛ لم يُجرَ اتصال حي أو نشر أو تعديل إنتاجي. الدومين المقصود هو `chatora.ansygroup.com`، وإعداد CNAME مسؤولية مالك النطاق. التفاصيل وحدود التحقق في **[DEPLOY.md](DEPLOY.md)**.

**طبقة الفورم المحلية:** `assets/js/api.js` ترسل إلى Supabase عند توفر الإعداد والاتصال. عند الانقطاع تحفظ حتى 60 إرسالًا محليًا وتعيد المحاولة؛ لا تعتبر أخطاء الخادم الدائمة أو فشل التخزين نجاحًا. هذا التدقيق لم يختبر وصول lead إلى قاعدة حية.

**الوضع الآمن للنشر:** `./_tools/deploy.sh` يبني محليًا فقط افتراضيًا. رفع الملفات إلى الـStorage العام يحتاج `ALLOW_SUPABASE_UPLOAD=YES`، ونشر Vercel Production يحتاج موافقة منفصلة عبر `ALLOW_VERCEL_PRODUCTION_DEPLOY=YES`، إضافةً إلى بيانات الاعتماد اللازمة. لا تستخدم بوابات النشر إلا بعد تصريح إطلاق صريح. انظر `DEPLOY.md`.

**التحقق المحلي الأخير (28 أكتوبر 2026):** تغطية المفاتيح المتتبعة 100% في اللغات الست؛ بُنيت 28 صفحة ثابتة لكل لغة (168 إجمالًا)، مع 3,449 سلسلة عربية و0 fallbacks، وsitemap من 150 URL (25 صفحة قابلة للفهرسة × 6 لغات). لكل صفحة `canonical` خاص و`hreflang` متبادل للغات الست و`x-default` إنجليزي؛ روجعت أوصاف JSON-LD والـbreadcrumbs و180 زوج سؤال/جواب FAQ مترجمًا. فحص axe لـ168 صفحة بلا مخالفات؛ و`linkcheck.py` راجع 12,356 مرجعًا محليًا و1,914 مرساة بلا أهداف مفقودة. فحص المتصفح للصفحات الـ168 لم يجد أخطاء JavaScript أو console أو طلبات محلية 4xx/5xx. اختُبر تبديل المسارات والعودة بين اللغات، والداشبورد ES→FR→AR عبر auth/API mock محلي فقط؛ لا يثبت ذلك مصادقة أو بيانات حية. اختُبرت 96 حالة استجابة عند 360 و768 بكسل بلا تجاوز أفقي. لم يُقَس Core Web Vitals، ولم يحدث نشر إنتاجي.

**بعد موافقة النشر الصريحة:**
1. تحقق من DNS/CNAME لـ`chatora.ansygroup.com` في لوحة مزود النطاق، ثم اختبر HTTPS من خارج بيئة البناء.
2. اربط Google Search Console وBing وأرسل `sitemap.xml` بعد التأكد من أن النشر عام.
3. راجع لقطات أسعار المنافسين المؤرخة ومصادرها دوريًا؛ لا تعرض أسعارًا أو خططًا من Chatora قبل اعتمادها ونشرها فعليًا.
4. تأكد من أن كل أرقام العملاء أو الشهادات أو النتائج حقيقية ومؤرخة، وبموافقة أصحابها.

## 10) تكامل Meta: WhatsApp + Instagram (مسودة محلية فقط)

الحالة في **27 أكتوبر 2026**: أضفنا محليًا تدفق WhatsApp Embedded Signup v4 وتدفق Instagram المرتبط بصفحة Facebook، مع endpoint آمن للتحقق من الملكية وتبادل الأكواد وتشفير التوكنات. أضفنا بطاقات ربط ثنائية اللغة في الإعدادات. الاختبارات محلية/بمحاكاة الطلبات فقط؛ **لم تُطبّق أي migration، ولم تُنشر Edge Functions، وإعدادات Meta العامة فارغة، ولا يوجد حساب مربوط**.

- دليل الإعداد والمتطلبات: [`docs/integrations/META_WHATSAPP_INSTAGRAM.md`](docs/integrations/META_WHATSAPP_INSTAGRAM.md)
- OAuth/Embedded Signup المحلي: `supabase/functions/meta-connect/index.ts`
- عميل Facebook JS SDK: `assets/js/meta-onboarding.js`
- بطاقات الربط وقائمة تحقق لوجود IDs العامة: `assets/js/app.js` و`_pages/app.html`
- Webhook الوارد: `supabase/functions/meta-webhook/index.ts`
- normalizer مشترك للـWebhook وإعادة المعالجة: `supabase/functions/_shared/meta-webhook-normalize.ts`
- إعادة معالجة آمنة لصفوف الـWebhook المؤجلة: `supabase/functions/meta-replay/index.ts` (ذو secrets مستقلة وatomic claims؛ غير منشور وغير مجدول).
- API إرسال الردود: `supabase/functions/meta-send/index.ts`، وعميل المتصفح المقفول افتراضيًا: `assets/js/meta-send-client.js`.
- تنظيف مدد الاحتفاظ بعد الجدولة: `supabase/functions/meta-retention/index.ts` (يمسح OAuth states المنتهية وصفوف webhook بعد `expires_at`؛ غير منشور وغير مجدول).
- مسودة قاعدة البيانات غير المطبّقة: `supabase/migrations/20261027_meta_channel_scaffold.sql`
- فحص جاهزية محلي وغير متصل بالشبكة: `node _tools/meta-preflight.mjs` (يعرض IDs الناقصة ولا يقرأ أسرارًا أو يغيّر إعدادًا؛ exit code 2 ما دامت القيم ناقصة).
- الاختبارات المحلية: `node supabase/functions/meta-webhook/smoke_test.mjs` و`node supabase/functions/meta-send/smoke_test.mjs` و`node assets/js/meta-send-client.smoke_test.mjs` و`node supabase/functions/meta-connect/smoke_test.mjs` و`node supabase/functions/meta-replay/smoke_test.mjs` و`node supabase/functions/meta-retention/smoke_test.mjs`

اختيار مسار المزوّد لا يثبت حصول الموافقة؛ المستخدم اختار محليًا مسار Tech Provider، والموافقة نفسها غير متحققة. App ID وConfig IDs فاضية، و`META_ONBOARDING_ENABLED` متوقف. واجهة الرد مرتبطة بالـAPI لكن بوابتها العامة وخاصية `META_SEND_ENABLED` على الخادم متوقفتان، لذلك لا يمكن إرسال رسائل. عاملا replay والتنظيف موجودان محليًا لكنهما غير منشورين أو مجدولين؛ يلزم إعداد جدولة موثوقة واختبارهما عند الإطلاق. القوالب والبث والأتمتة خارج النطاق الحالي. لا تضع أي App Secret أو Token في ملفات المتصفح أو المحادثة، ولا تطبّق الميجريشن أو تنشر قبل موافقة صريحة.

## 11) خادم MCP محلي

أُضيف مشروع MCP معزول في [`mcp/`](mcp/). يوفّر بحثًا وقراءةً لصفحات sitemap العامة، وقراءة مساحة عمل المستخدم المصادَق عليها مع أفعال محدودة مثل إنشاء/تعديل مسودة تدفق أو إضافة جهة اتصال. يعمل عبر STDIO أو Streamable HTTP محلي على loopback؛ أدوات المساحة العمل تستخدم JWT المستخدم ومفتاح Supabase العام، ولا تستخدم `service_role`. لا يرسل رسائل ولا يفعّل أتمتة ولا يربط Meta.

دليل التشغيل وإعداد Claude Desktop وVS Code/Cursor وCodex: [`mcp/README.md`](mcp/README.md). توجد أداة preflight حية اختيارية ولا تعمل إلا بطلب صريح، كما يوجد scaffold OAuth متوقف افتراضيًا موثّق في [`mcp/OAUTH.md`](mcp/OAUTH.md). اختبارات MCP تستخدم Supabase mock فقط؛ لم يحدث اتصال بقاعدة حية أو تعديل Dashboard أو نشر. HTTP ما يزال loopback-only، فلا تعرّضه للإنترنت.
